Two consequences for the production decision:

1. **Training dominates.** The 1M-step ceiling is 1.5-3 A10-days. A convergence

2. **Evaluation is affordable but not free.** A pilot on a seeded random
   sub-sample is cheap, but note the statistics: at p ≈ 0.99, a 1,000-puzzle
   pilot gives a Wilson half-width of ~0.6 pp, which cannot separate the
   predeclared 98.78% strong-replication boundary from the 99.28% target. Only
   the full 10,000 puzzles (half-width ~0.2 pp) resolves it. Budget for the
   full set.

These are arithmetic, not measurements. §9 exists to replace them.

## 11. Minimal interfaces for a later geometric-attention ChessFormer replacement

Not implemented, as instructed. The seam is deliberately narrow: only
`repro/model.py` is architecture-aware. Losses, sampler, evaluator, trainer,
manifest, telemetry and supervisor depend on the backbone through four things
only.

**Required contract for any replacement backbone:**

1. `forward(indices: LongTensor[B, L], sigma: Optional[Tensor] = None) -> Dict[str, Tensor]`
   returning exactly `unmasking_logits [B, L, V]`, `remasking_logits [B, L, 1]`,
   `expansion_logits [B, L, 1]`, `contraction_logits [B, L, 1]`. These four keys
   are the entire coupling to `repro.losses.supervised_loss`,
   `repro.losses.head_diagnostics` and `repro.sampler.generate`.
2. Attributes `max_length: int`, `vocab_size: int`, and standard
   `nn.Module.parameters()` (the sampler reads `next(model.parameters()).device`).
3. `architecture_signature() -> str` and `parameter_count() -> ParameterCount`.
   Changing the signature is what makes old checkpoints and manifests
   automatically incompatible — `repro.evaluator.check_evaluation_preconditions`
   and `Trainer.load_checkpoint` both compare it, so no extra plumbing is needed.
4. Reject out-of-range token ids, wrong rank, and `L > max_length` by raising
   `ValueError`, as `APMDMEncoder` does.

**The one genuinely new interface a geometric model needs** is board geometry,
which the current encoder does not receive: it sees a flat 324-token stream and
recovers order only through RoPE. A ChessFormer-style geometric attention needs,
per position, the structural coordinates — all of which are already derivable
and already implemented as scalar helpers in `repro/vocab.py`:

```
cell  = position // 4                 # repro.vocab.cell_of
slot  = position %  4                 # repro.vocab.slot_of  (value/colour/marker/separator)
row   = cell // 9
col   = cell %  9
box   = (row // 3) * 3 + (col // 3)
```

The minimal additions are therefore:

* a `geometry_tensors(length) -> {row, col, box, slot, cell}` helper in
  `repro/vocab.py` (pure function of length, cacheable), plus the derived
  same-row / same-column / same-box / same-cell boolean adjacency masks a
  geometric attention bias would consume;
* a backbone **registry** in `repro/model.py` keyed by `config.model.name`, so
  `build_model` and `count_parameters` can dispatch without any other module
  changing;
* additive `ModelSpec` fields describing the board (`grid_rows`, `grid_cols`,
  `tokens_per_cell`, and whatever bias parametrisation the geometric attention
  needs). Because `ModelSpec.signature()` is built from the field set, adding
  them automatically produces a distinct signature;
* a new `train/configs/sudoku_chessformer.yaml`, additive in exactly the same
  way `sudoku_paper.yaml` is additive to `sudoku.yaml`.

**Two constraints a geometric replacement must respect.** First, the sampler
supports variable-length sequences (the insert/delete path); a model that hard-
codes 324 positions must raise on any other length rather than mis-index, so the
anomaly is recorded instead of silently corrupting a row. Second, the geometry
is a property of the *state encoding*, not of the task: `repro/data.py`'s
`encode_puzzle_state` and the official generator both assume
`(value, colour, marker, separator)` cells in row-major order, so any change to
the encoding invalidates the transition store and must go through
`repro.cli generate` again with a fresh index digest.

No change to `repro/losses.py`, `repro/sampler.py`, `repro/evaluator.py`,
`repro/trainer.py`, `repro/manifest.py`, `repro/telemetry.py` or
`repro/supervisor.py` is required.

## 12. Honest summary

* Every authoritative input authenticates. Train/test leakage is zero, measured four ways.
* The paper's central data claim — 100 source puzzles expanding to ~25,022.6 supervised transitions each — reproduces **exactly** (25,022.58; 2,502,258 total), and every transition satisfies the paper's Algorithm 1.

That evaluator is reconstructed here from Algorithm 1 and validated against the generator, but it is a reconstruction and is the largest threat to a faithful comparison.
